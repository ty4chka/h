# План развития HYDRA (единый движок)

Статус-кво: один движок `hydra_kernel` грузит все родные модули через compat
(`setup(client)` / `<cmd>_handler` / `register(kernel)` / class-MCUB / noop).
Сборка `python3 -m hydra_kernel.tools.build` — единственный приёмочный контур:
каждая фаза ниже заканчивается своим чеком в build.py.

---

## Фаза 1 — метаданные модулей  ✅ (старт)
- Строка `# meta: name=… version=… author=… requires=… framework=…` в каждом
  модуле (родные + демо). `requires` настоящий: ServerInfo/start/terminal → lang.
- resolver строит порядок загрузки по requires (уже умеет).
- Чек build: у каждого модуля version ≠ 0.0.0 и имя совпадает с файлом.

## Фаза 2 — проверка работы ВСЕХ родных модулей  ✅
- Отдельный suite на модуль: гоняем главные команды через фейковый клиент:
  lang (.lang/.mylang), terminal (.terminal_info), cfg (схема .cfg),
  ServerInfo (.serverinfo), start (.start), hloader (.hmods), protect (статус),
  approve (форма/кнопки), convert (без сети — только загрузка и справка).
- Ломающееся чиним по ходу (compat-дырки в kernel, а не в модулях).

## Фаза 3 — полная совместимость с модулями других юб  ✅ (настоящие Hikka через hikkatl-алиас, Dragon через pyrogram-шим, Heroku — было)
- Реальные модули: Heroku (refs есть), Hikka, Dragon — добавить refs-клоны.
- Build-цели: загрузка + прогон ключевой команды каждого чужого модуля
  (сейчас цели есть на translations-модулях; расширяем до 2–3 модулей на юб).

## Фаза 4 — пак MCUB-модулей  ✅ (18/18 модулей MCUB-fork грузятся, пак в extras/mcub_pack)
- refs/mcub/modules пуст → ищем каталог MCUB-модулей на GitHub (MCUB-fork и ко).
- 3–5 реальных MCUB-модулей грузим единым движком, дыры compat/mcub чиним
  (conversations, inline-формы, config-схемы).

## Фаза 5 — текстовый модуль  ✅ (modules/text.py: .text upper|lower|title|mock|reverse + форма)
- Новый hydra-модуль `text`: `.text upper|lower|title|mock|reverse`, счётчик
  слов/символов, форма с кнопками (+ `.it` для ввода), метаданные по Фазе 1.

## Фаза 6 — менеджер при запуске  ✅ (волновая параллельная загрузка, настоящая таблица имя/framework/версия/статус, хоткеи e/r/q, boot-метр)
- TUI-boot: таблица модулей (имя / framework / статус), хоткеи:
  `e` — редактор, `r` — перегрузить модуль, `q` — выход;
- параллельная загрузка модулей (asyncio.gather по независимым requires),
  убрать косметические sleep из прогресса m.py.

## Фаза 7 — нормальный редактор модулей (без nano)  ✅ (подсветка, поиск /, undo Ctrl+Z, :N/:w/:q, ast-валидация + .bak, авто-перезагрузка после выхода)
- Встроенный TUI-редактор: подсветка питона, поиск `/`, undo `u`,
  переход к строке `:N`, сохранение с ast-валидацией + резервная копия `.bak`,
  автоперезагрузка модуля после сохранения.

## Фаза 8 — оптимизация  ✅ (ленивые импорты, get_me без сети, cython-кэш по mtime, строка boot: X.XXs)
- Ленивые импорты (aiohttp/qrcode только при использовании),
- кэш `get_me`, кэш компиляции Cython/Go (не пересобирать без изменений),
- замер времени старта по фазам + строка «boot: X.XXs» в статусе.

---

Порядок: 1→2→3→4→5→6→7→8. Каждая фаза мерджабельна отдельно,
сборка зелёная после каждой.
