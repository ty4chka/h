# Plan: Идеальный адаптер MCUB-модулей для Hydra

## Проблемы текущей реализации

1. **`core/lib/loader/module_config.py` — дубликат `module_base.py`** (187 строк идентичного кода). Нужно объединить.
2. **Функциональный стиль (fheta, gemini, dnd, sourcetrigger, last-fm)**: адаптер генерирует огромный `_KernelMock` прямо в adapter.py (~150 строк кода в виде строк), вместо того чтобы использовать уже существующий `KernelMock` из `module_base.py`. Дублирование логики.
3. **OOP bootstrapper**: генерирует `init_logic` с повторяющимся кодом для каждого хэндлера. Если `on_load()` бросает исключение — модуль ломается молча.
4. **`post_process()` опасен**: вырезает `self.` из кода если нет `ModuleBase` в тексте, но может сломать любой код с `self.` (например, pyrogram модули).
5. **`utils/__init__.py` пустой**, а `register_placeholder` и др. уже в `utils/misc.py`.
6. **Нет валидации результата** — адаптированный код может быть невалидным Python, а hloader просто молча проглатывает ошибку.
7. **Client proxy дублируется** в 3 местах: adapter.py, module_base.py, module_config.py.

## Решение

### Файл 1: `core/lib/loader/module_base.py` (переписать)

Объединить `module_base.py` + `module_config.py` в один файл. Содержимое:

- `LoopHandle` (без изменений)
- Декораторы: `command()`, `inline()`, `callback()`, `on_install()`, `on_uninstall()`, `event()`, `watcher()`, `loop()` (без изменений)
- `StringsMock` (без изменений)
- `DBMock` (без изменений)
- `KernelMock` (без изменений, уже есть `client` property с SafeClientProxy)
- `ModuleBase` (без изменений)
- **Новое**: `ConfigValue`, `ModuleConfig`, `String`, `Boolean`, `Choice`, `Integer`, `Float`, `Secret` — простые эмуляторы из MCUB `module_config.py`. Это позволяет MCUB-модулям импортировать `from core.lib.loader.module_config import ModuleConfig, ConfigValue, ...` без ошибок.

### Файл 2: `core/lib/loader/module_config.py` (переписать)

Прокси-файл, который просто импортирует всё из `module_base.py`:

```python
from core.lib.loader.module_base import (
    LoopHandle, command, inline, callback, on_install, on_uninstall,
    event, watcher, loop, StringsMock, DBMock, KernelMock, ModuleBase,
    ConfigValue, ModuleConfig, String, Boolean, Choice, Integer, Float, Secret,
)
```

Это гарантирует обратную совместимость: `from core.lib.loader.module_config import ModuleConfig` продолжит работать.

### Файл 3: `modules/adapter.py` (переписать)

Ключевые изменения:

#### 3a. Упростить `adapt_mcub_core()` для функционального стиля

Вместо генерации 150+ строк кода `_KernelMock` прямо в строках, адаптер будет добавлять импорт и вызов:

```python
# Вместо инлайна всего _KernelMock — просто:
from core.lib.loader.module_base import KernelMock as _KernelMock
```

И добавить bootstrapper который:
1. Создаёт `_kernel_inst = _KernelMock(None)`
2. Патчит `_kernel_inst.client` через `SafeClientProxy` 
3. Вызывает `register(_kernel_inst)`
4. Устанавливает `modules_help` из собранного `_fheta_help`

Проблема: `KernelMock.__init__` требует `parent_module`. Решение — передать объект с `client` атрибутом.

#### 3b. Улучшить OOP bootstrapper

- Добавить try/except вокруг `on_load()` с логированием
- Не дублировать `init_logic` для каждого хэндлера — вынести в общую функцию `_ensure_client(event)`

#### 3c. Исправить `post_process()`

```python
def post_process(code: str, module_type: str = "unknown") -> str:
    code = re.sub(r'\n\n\n+', '\n\n', code)
    # Удалять self. ТОЛЬКО для hikka/heroku/dragon модулей
    if module_type in ("hikka", "heroku", "dragon"):
        code = re.sub(r'self\.(?!(client|db|inline|me|get_prefix|invoke|lookup|request_join))', '', code)
    # Валидация
    try:
        ast.parse(code)
    except SyntaxError as e:
        lines = code.split('\n')
        insert_idx = 0
        for i, line in enumerate(lines):
            sline = line.strip()
            if sline.startswith(('from __future__', '"""', "'''", '#')):
                continue
            insert_idx = i
            break
        lines.insert(insert_idx, f"# ⚠️ Syntax check failed: {e}")
        code = '\n'.join(lines)
    return code
```

#### 3d. Добавить валидацию `adapt_module()`

```python
def adapt_module(code: str, module_name: str) -> tuple:
    t = detect_module_type(code)
    adapted_code, adapted_type, was_adapted = _do_adapt(code, module_name, t)
    if was_adapted:
        adapted_code = post_process(adapted_code, t)
    return adapted_code, adapted_type, was_adapted
```

#### 3e. Экспортировать `post_process` с правильной сигнатурой

`hloader.py` вызывает `post_process(code)` — нужно добавить `module_type="unknown"` по умолчанию.

### Файл 4: `modules/hloader.py` (минимальные правки)

- Передавать `module_type` в `post_process(code, module_type)`
- Добавить логирование ошибок адаптации в `show_error()` при падении загрузки

### Файл 5: `utils/__init__.py` (не трогать)

Уже пустой. `register_placeholder` и др. уже в `utils/misc.py`. Всё ок.

## Верификация

1. **Синтаксис**: `python -c "import ast; ast.parse(open('modules/adapter.py').read()); print('OK')"` для каждого изменённого файла
2. **Импорты**: `python -c "from core.lib.loader.module_base import ModuleConfig, ConfigValue, String, Boolean, Choice, Integer, Float, Secret; print('OK')"`
3. **Прокси**: `python -c "from core.lib.loader.module_config import ModuleConfig; print('OK')"`
4. **Интеграция**: проверить что `.lm <mcub_module>` корректно адаптирует и загружает (fheta, sourcetrigger, gemini, dnd, last-fm)
5. **Edge cases**: модули с `@watcher()`, `@inline()`, `@callback()`, `loop()`, `kernel.register_callback_handler()`
